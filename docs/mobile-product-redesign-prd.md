# 茶馆移动端产品重构 PRD

版本：v0.1  
分支：`mobile-product-redesign`  
范围：仅移动端 Web，PC 端不改造  
登录约束：`/login`、`/login/student-oauth` 保持现有 PC 端登录页和登录逻辑，不纳入移动端新版 UI

## 1. 信息来源和判断原则

### 1.1 信息来源

- 本地切图：
  - `所有切图/pages/*`：页面状态参考。
  - `所有切图/components/*`：局部组件、尺寸、间距和状态参考。
  - `所有切图/icons/*`：可复用图标资源。
  - `所有切图/decorations/*`：茶杯、个人主页背景等固定装饰资源。
  - `所有切图/reference/design-board-1x.png`：全局页面关系和状态补充。
- MasterGo MCP：
  - 设计稿容器：`file=194995124550384&layer_id=96:0951`。
  - 可用信息：颜色、字号、阴影、页面层级、部分图片 URL。
  - 关键 token：`#FE9800`、`#FFC641`、`#F9FAFC`、`#1A202C`、`#7F838A`、`#D8D8D8`，Source Han Sans/Poppins/Inter 字体体系，轻阴影与模糊背景。
- 现有前端和 API：
  - `src/mobile/api.ts`
  - `src/mobile/pages/*`
  - PC 端现有页面入口和路由分支。

### 1.2 产品判断原则

设计稿是信息源，不是像素圣旨。移动端新版以用户体验闭环为第一位：

- 优先真实内容、真实状态、真实反馈，不展示示例数据冒充内容。
- 保留设计稿的暖橙、茶杯、身份卡、茶评榜单等识别点。
- 重构布局时追求清爽、克制、有层次、类似 iOS 的触感和动效。
- 固定装饰可以用 MasterGo 切图；动态内容必须用 DOM 和接口数据。
- PC 端完全不变。
- 登录页不做移动端新版，沿用当前 PC 端登录页。

## 2. 产品定位

茶馆移动端是校园社区的轻量入口，用户在手机上完成四类核心任务：

1. 浏览和参与校园帖子：看帖、搜索、按茶桌进入、评论、点赞、收藏、举报、发帖。
2. 参与茶评榜单：浏览榜单、创建榜单、添加评分对象、评分、看点评、收藏榜单。
3. 维护个人身份：看我的主页、编辑资料、查看发帖和收藏、关注别人、私信。
4. 处理消息和反馈：看通知/私信、提交反馈、投诉不良内容。

移动端不应只是 PC 的压缩版，而应是一套适合单手浏览、低摩擦发布、快速反馈的手机体验。

## 4. 概念定义

### 4.1 茶桌

茶桌是官方内容分区，不是用户随意创建的标签。

- 作用：承载内容语境，帮助用户快速进入某类校园讨论。
- 数据：提交和查询仍使用后端 `post.category`。
- 移动端展示名可以和后端 category 不完全一致，由移动端常量映射。
- MVP 不开放用户自定义茶桌。
- 茶桌可以有固定头像式视觉，用 CSS 或内置 SVG/PNG 生成，不需要图床。

推荐茶桌结构：

| 移动端展示        | 后端 category         | 典型内容                     |
| ----------------- | --------------------- | ---------------------------- |
| 即时 吐槽 树洞    | 吐槽                  | 情绪、随手求助、匿名感倾诉   |
| 学习 决策 经验    | 学习                  | 课程、考试、保研、选择经验   |
| 比赛 项目 实践    | 艺术或后续新 category | 组队、复盘、项目经验         |
| 感情 成长 回顾    | 情感                  | 关系、成长、阶段总结         |
| 校园生活 日常经验 | 闲聊                  | 校园服务、生活技巧、日常问题 |
| 闲置 出物 互助    | 八卦或后续新 category | 闲置、互助、转让             |

### 4.2 标签

标签是帖子或榜单下的细分类。

- 标签可以来自茶桌预设。
- 发帖时允许选择 1 到 3 个标签。
- 允许用户添加短自定义标签，但应限制长度和数量。
- 标签用于茶桌详情筛选，不替代茶桌。

### 4.3 茶评

茶评是“榜单 + 评分对象 + 用户点评”的复合产品。

- 榜单：一个主题容器，例如“奶茶新品榜”。
- 评分对象：榜单里的具体项目，例如某个饮品。
- 评分：用户对评分对象给星级和文字评价。
- 榜单收藏和帖子收藏是两个不同 target type。

## 5. 全局视觉与交互规范

### 5.1 风格目标

关键词：暖、轻、干净、圆润、灵动、不幼稚、不像 AI 模板。

具体策略：

- 背景以 `#F9FAFC` 或更柔的浅灰为底。
- 页面主体使用白色、半透明白、轻阴影形成层次。
- 主色保留橙色和黄色：`#FE9800` 用于重点图标/状态，`#FFC641` 用于主按钮。
- 文字用 `#1A202C`，辅助文字用 `#7F838A`。
- 卡片圆角以 8 到 16px 为主，底部浮层和搜索框可使用更圆的胶囊形。
- 列表行和卡片要有呼吸感，不要密成 PC 表格，也不要堆装饰。

### 5.2 动效

- 页面进入：不做重动画，使用自然加载和内容淡入。
- 点按反馈：按钮和卡片 `scale(0.98)` 或背景轻变，150 到 200ms。
- 折叠展开：高度或透明度过渡 180 到 240ms，禁止突兀跳变。
- 底部 sheet：从底部上滑，背景 `rgba(18, 27, 41, 0.45)` 或 blur。
- Toast：居中或底部轻提示，1.5 到 2 秒自动消失。

### 5.3 长文本和越界策略

- 页面标题：单行省略，必要时缩小到 18px。
- 帖子标题：列表中最多 2 行，详情中自然换行。
- 摘要：最多 3 行，超出省略。
- 用户昵称：最多 10 字，超出单行省略。
- 签名：主页最多 1 行，编辑页限制 40 字。
- 茶桌名：最多 2 行，不拆单字。
- 榜单名：列表最多 1 到 2 行，详情自然换行。
- 评论：详情页自然换行，列表预览最多 3 行。
- 图片：使用固定比例容器，避免加载后撑开布局。

### 5.4 状态规范

所有列表必须有四态：

- loading：骨架屏或非内容型 loading，不可显示示例数据。
- empty：说明当前没有内容，并给出可行动作。
- error：展示重试按钮。
- data：真实数据。

所有头像必须有兜底：

- 接口头像可用：显示接口头像。
- 接口空或默认占位：显示统一默认头像。
- 图片 404：回退默认头像。

## 6. 用户动线

### 6.1 浏览帖子动线

入口：

- 首页打开 App。
- 从搜索进入。
- 从茶桌分类进入。
- 从通知、个人主页、收藏进入某帖子。

完整路径：

1. 首页看推荐/最新帖子。
2. 点击茶桌进入茶桌详情，按标签或最新/热门筛选。
3. 点击帖子卡片进入帖子详情。
4. 在详情中阅读正文、图片、评论。
5. 用户可以点赞、收藏、评论、回复、举报、进入作者主页。
6. 操作成功后原地反馈，计数即时更新。

异常和边界：

- 未登录时执行互动动作，跳转现有登录页。
- 帖子不存在，显示 404 或“帖子已被删除”。
- 评论失败保留输入内容。

### 6.2 发帖动线

入口：

- 首页悬浮发布按钮。
- 茶桌详情悬浮发布按钮。
- 帖子详情编辑自己的帖子。

完整路径：

1. 进入编辑页。
2. 选择茶桌。
3. 填标题。
4. 写正文。
5. 上传图片，可选。
6. 选择或自定义标签。
7. 发布。
8. 发布成功进入帖子详情。

产品要求：

- 自动保存草稿。
- 退出前有未保存确认。
- 标题、正文、标签是必填。
- 图片走七牛上传。
- 摘要由正文自动生成。

### 6.3 茶评动线

入口：

- 底部 Tab 茶评。
- 个人主页的榜单收藏。
- 帖子或搜索中未来可以扩展榜单入口。

完整路径：

1. 茶评首页浏览热门/最新榜单。
2. 搜索榜单。
3. 点击榜单进入榜单详情。
4. 查看榜单简介、评分对象排行。
5. 点击评分对象进入详情。
6. 评分、写点评、上传图片。
7. 回到详情后评分和点评列表更新。

创建路径：

1. 茶评首页点击建榜。
2. 填写榜单名称、简介、封面、分类或标签。
3. 创建成功进入榜单详情。
4. 添加评分对象。

### 6.4 个人主页动线

我的主页：

1. 底部 Tab 进入我的主页。
2. 查看头像、昵称、签名、关注数、粉丝数。
3. 展开我发过的帖子。
4. 展开我的收藏，再展开帖子收藏或榜单收藏。
5. 进入编辑资料、反馈、退出登录。

他的主页：

1. 从帖子作者、评论作者、茶评作者进入。
2. 查看资料、发帖、公开收藏。
3. 关注或取消关注。
4. 发起私信。

### 6.5 消息动线

入口：

- 首页或个人页右上角通知。
- 底部我的页中的消息入口，后续可补。

完整路径：

1. 消息中心默认显示全部。
2. 切换评论、@我、私信。
3. 点击通知进入对应帖子或评论位置。
4. 点击私信进入会话。

### 6.6 反馈和投诉动线

反馈：

1. 我的主页点击反馈与建议。
2. 选择问题类型。
3. 填写描述。
4. 上传图片，可选。
5. 填联系方式，可选。
6. 提交后 toast，并返回上一页或停留显示成功状态。

投诉：

1. 帖子详情或评论更多菜单点击投诉。
2. 选择投诉类型。
3. 填写补充说明。
4. 上传截图，可选。
5. 填联系方式，可选。
6. 提交成功后回到原页面。

## 7. 页面规格

### 7.1 首页 `/`

目标：让用户快速进入帖子流、茶桌和发布。

从上到下：

1. 顶部安全区和轻背景。
2. 搜索框：
   - 占位：“搜索茶馆”。
   - 点击聚焦，提交后跳转 `/search?query=xxx`。
3. 茶桌分类：
   - 3 到 6 个入口，首屏展示 3 个，支持横滑或两行网格。
   - 每个茶桌有固定头像、展示名。
   - 点击跳转 `/:category`。
4. 帖子流：
   - 默认最新，可在后续加入热门切换。
   - 帖子卡片包括茶桌名、作者、时间、标题、摘要、互动数。
   - 点击进入帖子详情。
5. 悬浮发布按钮：
   - 固定右下，避开底部 Tab 和安全区。
   - 点击 `/editor/article${Date.now()}`。
6. 底部 Tab。

边界：

- 加载时显示 loading 或骨架，不显示假帖子。
- 空态：“还没有帖子，来发第一条吧”并给发布按钮。
- 头像空值显示默认头像。

### 7.2 搜索页 `/search`

目标：查找帖子、茶桌或榜单，第一期先支持帖子搜索。

从上到下：

1. 顶部返回和搜索框。
2. 搜索结果摘要：
   - 有 query：显示“搜索 xxx”。
   - 无 query：展示搜索引导。
3. 结果列表：
   - 帖子卡片和首页一致。
4. 空态：
   - “没有找到相关内容”。
   - 提供清空搜索或返回首页。

交互：

- 输入后回车搜索。
- 清除按钮清空 query。
- 后续可加搜索历史和热门茶桌。

### 7.3 茶桌详情 `/:category`

目标：让用户进入一个稳定的内容语境。

从上到下：

1. 顶部栏：
   - 返回、搜索茶桌、更多。
2. 茶桌 Hero：
   - 茶桌头像/插画。
   - 茶桌名。
   - 简介。
   - 今日帖子数或讨论数。
3. 标签筛选：
   - “全部”加茶桌预设标签。
   - 当前标签高亮。
4. 排序：
   - 最新、热门。
5. 精选卡片：
   - 只在有真实精选或第一条高热帖时展示。
   - 没数据时不展示示例内容。
6. 帖子列表。
7. 发布按钮。

边界：

- 标签名太长时横滑，不压缩到看不清。
- 茶桌简介最多 2 到 3 行，超出折叠。

### 7.4 帖子详情 `/article/:article_id`

目标：阅读完整内容并参与讨论。

从上到下：

1. 顶部栏：
   - 返回。
   - 标题：“帖子详情”或茶桌名。
   - 更多菜单。
2. 正文区：
   - 茶桌 chip。
   - 标题。
   - 作者头像、昵称、发布时间。
   - 正文 Markdown/富文本。
   - 图片区域，图片可预览。
   - 标签 chips。
3. 操作区：
   - 点赞、评论、收藏、举报。
   - 计数即时更新。
4. 评论区：
   - 评论总数。
   - 一级评论。
   - 回复预览，超过 2 条显示“查看全部回复”。
   - 评论图片。
5. 底部评论输入：
   - placeholder：“说点什么...”。
   - 支持回复状态。
   - 支持图片上传，可后续分期。

边界：

- 长标题自然换行。
- 代码块或长 URL 横向滚动，不撑破页面。
- 删除或不存在显示空状态。

### 7.5 发帖/编辑 `/editor/:id`

目标：低摩擦发布高质量帖子。

从上到下：

1. 顶部栏：
   - 返回。
   - 标题：发布帖子/编辑帖子。
   - 草稿状态文案，可选。
2. 茶桌选择：
   - 当前茶桌显示在右侧。
   - 点击打开横向 chip 或底部 sheet。
3. 标题输入：
   - 必填。
   - 最大 40 字。
4. 正文输入：
   - 多行输入，支持 Markdown 或纯文本。
   - 最大字数提示。
5. 图片上传：
   - 0 到 9 张。
   - 缩略图网格。
6. 标签：
   - 预设标签。
   - 自定义标签输入。
   - 1 到 3 个必选。
7. 底部发布按钮：
   - 固定底部。
   - 发布中禁用并显示 loading。

交互：

- 自动保存草稿。
- 返回前确认未保存改动。
- 发布成功跳转详情。
- 编辑成功返回详情。

### 7.6 茶评首页 `/sip-score`

目标：发现值得参与的榜单。

从上到下：

1. 顶部搜索和建榜按钮。
2. 排序 tabs：
   - 热门、最新。
   - 后续可加收藏、我参与。
3. 榜单卡片列表：
   - 榜单标题。
   - 收藏标识。
   - 查看完整榜单入口。
   - 前 3 个评分对象预览。

## 9. 数据和接口要求

- 首页/茶桌/搜索：`GET /post/list/:domain`

### 9.2 茶评

- 榜单列表：`GET /sip-score/list`
- 榜单搜索：`GET /sip-score/search`
- 新建榜单：`POST /sip-score`
- 榜单详情：`GET /sip-score/:id`
- 评分对象列表：`GET /sip-score/entries/list/:id`
- 添加评分对象：`POST /sip-score/entries`
- 评分对象详情：`GET /sip-score/entry/:sip_score_id/:entry_id`
- 提交评分：`POST /sip-score/entry/rating`
- 评分列表：`GET /sip-score/entry-rating/list/:sip_score_id/:entry_id`
- 创建榜单：`GET /sip-score/created/:user_id`
- 收藏榜单：`GET /sip-score/collected/:user_id`

### 9.3 用户和消息

- 我的资料：`GET /user/myprofile`

- 编辑资料：`PUT /user`

- 消息：`GET /user/private_message/list`
- 私信用户：`GET /chat/userList`
- 私信历史：`GET /chat/history/:id`

## 11. 重构优先级

### P0 基础体验闭环

- 统一移动端 Shell、TopBar、BottomTabs、Loading、Empty、Error。
- 保持登录页 PC 原样。
- 首页、茶桌、搜索、帖子详情、发帖可完整闭环。
- 个人主页、编辑资料、收藏、反馈可完整闭环。
- 茶评首页、榜单详情、评分对象详情、建榜可完整闭环。

### P1 体验和美观提升

- 更果味的卡片、动效、底部 sheet、toast。
- 列表骨架屏和错误重试。
- 图片预览。
- 评论回复定位。
- 茶桌视觉系统。

### P2 扩展能力

- @我真实后端类型。
- 私信 unread 和最后一条消息。
- 茶评评分评论的回复/点赞。
- 茶桌配置后台化。
- 搜索扩展到榜单和用户。

## 12. 当前设计稿问题和优化方向

设计稿存在的问题：

- 多处元素位置散乱，信息密度和留白不稳定。
- 一些状态页只是重复截图，未形成完整交互闭环。
- 个人主页展开区容易把重要操作挤到屏幕外。
- 茶评卡片视觉有辨识度，但列表高度偏大，需要减少首屏浪费。
- 发帖和反馈表单过于平，缺少状态提示和输入约束。
- 登录页不适合纳入这轮移动端改造，应保持现有稳定流程。

优化方向：

- 以用户任务为中心，不按切图机械堆页面。
- 用固定视觉 token 保持设计一致。
- 关键入口更稳定：搜索、发布、消息、我的。
- 所有列表都要有清晰状态。
- 用底部 sheet 承载轻任务，减少页面跳转。
- 动态内容必须来自接口，不再使用示例数据。

## 13. 验收标准

### 13.1 功能验收

- 手机宽度访问 `/login` 仍是现有登录页。
- 首页能加载真实帖子，loading 不展示示例帖子。
- 茶桌详情能按标签和排序筛选。
- 帖子详情能点赞、收藏、评论、举报。
- 发帖成功后进入详情。
- 茶评能建榜、添加评分对象、评分、收藏榜单。
- 个人主页能编辑资料、查看帖子和收藏、关注、私信。
- 反馈和投诉能提交并保存图片和联系方式。

### 13.2 视觉验收

- 375、390、440 三个宽度无横向滚动。
- 底部 Tab 不遮挡内容。
- 长标题、昵称、签名、标签不越界。
- 空态、加载态、错误态都有明确展示。
- 切图装饰清晰不拉伸。
- 设计整体保持暖橙和茶馆识别，但布局更干净、更像手机 App。

### 13.3 回归验收

- PC 页面不进入移动端 UI。
- `/login`、`/login/student-oauth` 不使用移动端新版登录 UI。
- 现有 PC 首页、帖子详情、编辑器、个人主页仍可用。
